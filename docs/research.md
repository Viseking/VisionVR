# Research Notes

## Hardware and platform exploration

- OpenXR is the preferred interoperability baseline.
- Meta Quest and SteamVR-compatible environments are natural early targets.
- A PCVR-first prototype is a pragmatic path for rapid iteration.
- Hand tracking, controller mapping, and spatial ergonomics will define product comfort.

## Software stack direction

Recommended starting stack:

- Unity 3D for XR-heavy app prototyping
- WebXR for lightweight browser-based demos
- C# and C++ for runtime and platform services
- Python for tooling, calibration scripts, and research workflows

## Key questions to answer

- Which users are the first release optimized for?
- Which VR hardware should be supported in v1?
- Which interactions are simplest and least physically tiring?
- What is the smallest persuasive spatial workspace demo?

## Conclusion

The most realistic technical path is a focused workspace-driven product with a compatibility layer, a UI runtime, and a small but polished MVP.
